Python Fundamentals

The building blocks: tokens, variables, data types, operators, expressions and statements. This is the chapter where "no type declarations" stops being a curiosity and starts being something to actually teach carefully.

C++ — types are declared up front
int a = 5;
float b = 2.5;
// type is fixed forever
Python — types follow the value
a = 5
b = 2.5
print(type(a), type(b))
runs instantly · fully offline
Same variable, no declared type — Python asks the object, not the variable, what type it is. Watch this idea resurface constantly this chapter.
5.1 – 5.2 · Character set & tokens

The alphabet before the words

Every Python statement is built from characters (letters, digits, symbols, whitespace) grouped into tokens — the smallest meaningful units. Python has five token types: keywords, identifiers, literals, operators and punctuators.

🔑

Keywords

Reserved words with fixed meaning — you can't use them as variable names. Python is case-sensitive: True is a keyword, true is not.

🏷️

Identifiers

Names you create for variables, functions, classes. Must start with a letter or underscore, no spaces or special characters, and can't be a keyword.

Teaching tip

C++ students already accept "reserved words" from int/class/return, so this concept isn't new — only the specific list is. The one that trips people up: Python's soft keywords (match, case) are only reserved in certain contexts, unlike C++'s all-or-nothing reserved words. Save the detail for Chapter 6.

A literal is a token that represents a fixed value — string, numeric, Boolean, or the special value None. Python also groups literals into collections: lists, tuples, dictionaries and sets.

5.3 – 5.4 · Variables & data types

A name, an object, and a type that can change

A variable is an identifier bound to an object in memory. That object carries three things: an identity (its memory address), a type, and a value. Try the exact demonstration from the textbook below.

Teaching tip

The variable num doesn't have a fixed type — the object it currently refers to does. Assigning num = 3.5 after num = 10 doesn't convert an int to a float; it points num at a brand-new float object. This is the single biggest mental model shift for a C++ class this chapter.

Teaching tip

temp = num makes both names point at the same object — num is temp is True. But num = num * num creates a brand-new object (int is immutable) and re-points num at it; temp still refers to the old object with value 10. That's why the final num is temp flips to False. This maps cleanly to C++ pointer/reference intuition if your teachers already have it.

"Good" < "good" is True — uppercase letters have smaller Unicode values than lowercase. Worth a live "guess before you run" moment.

Python spells these out as words: and, or, not — where C++ uses &&, ||, !. Unlike C++, they don't just return True/False — they return one of the actual operands.

Teaching tip

3 and 0 gives 0, not False — and/or return an actual operand, not a boolean. This surprises C++ programmers every time; it's worth dwelling on.

Compound assignment works exactly like C++'s += family — Python just adds **= and //= to match its extra arithmetic operators.

"15" in a is False even though 15 is in the list — the string "15" and the int 15 are different types. A quick, memorable illustration of why type matters.

Comments

Single-line comments start with # — same symbol, same idea as C++'s //. Multi-line comments use a pair of triple quotes ("""…""") instead of C++'s /* … */.

Wrap-up

Session summary

Today: the five token types, how variables reference objects rather than "contain" values, the six operator families, how precedence resolves multi-operator expressions, and the input → process → output shape of a first program.

Five habits to reinforce with C++ students

  • A variable's type comes from its current object, not a declaration — and it can change.
  • and / or / not replace && / || / !, and don't always return a strict boolean.
  • / always gives a float; use // for integer-style division.
  • input() always returns a string — wrap it in int() or float() before doing arithmetic.
  • is checks identity (same object), == checks equality (same value) — they are not interchangeable.
