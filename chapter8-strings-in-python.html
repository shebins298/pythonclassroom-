Strings in Python

C++ needs a whole class — std::string, or worse, a raw char array — just to hold text. Python strings are a built-in type with indexing, slicing, and formatting baked in, and they're immutable: once created, a string never changes in place.

C++ — a class, with methods called on it
string name = "Alice";
cout << name.substr(0, 3);
name[0] = 'a';   // mutable
Python — a built-in type, sliceable, immutable
name = "Alice"
print(name[0:3])
name[0] = 'a'   # TypeError
runs instantly · fully offline
Slicing (name[0:3]) replaces substr(), and there's no in-place character assignment — strings are immutable. Trying name[0] = 'a' is a TypeError, not silently allowed.
8.1 · What is a string

A sequence of characters

A string is a sequence of characters enclosed within single quotes (' '), double quotes (" "), or triple quotes (''' ''' or """ """) — letters, digits, special characters, spaces, all of it. A single character is just a string of length one. Each character is reached through an index, always an integer, always starting at 0. And unlike a C++ char array, a Python string is immutable — once created, it can't be changed in place.

Teaching tip

Triple quotes matter because they let a string span multiple lines and contain the other quote character freely. A single- or double-quoted string ends at the first matching quote it sees — 'It's Python' breaks, because the apostrophe in "It's" closes the string early. Either escape it ('It\'s Python') or, cleaner, use the other quote style: "It's Python".

String creation and indexing

Every character has a position

Index numbering starts at 0 from the left. Python also allows negative indices, counting backward from −1 at the last character — handy when you want "the last three characters" without first computing the string's length.

8.2 · input() function

Collecting text while the program runs

A built-in method used to collect user input during program execution.

Syntax: var = input(prompt) — it always returns a string, even if the person types digits. That's why every numeric input in earlier chapters gets wrapped in int() or float().

ready ✓

Teaching tip

Ask the class what input("Enter your age") + 1 does. It raises a TypeError — input() handed back the string "25", not the number 25, and Python won't silently add a string and an int. Compare with C++'s cin >> age, which reads straight into a typed variable and never has this problem.

8.3 · f-strings

Formatting text without the plus signs

f-strings provide a simple, readable way to format and embed variables and expressions inside string literals. Place f or F right before the opening quote, and drop any expression inside { }.

Before f-strings, embedding a variable in the middle of text meant concatenating pieces together with + — and converting every non-string value with str() along the way.

ready ✓

The f-string version reads left to right, exactly like the sentence it produces — no stitching, no manual str() calls.

ready ✓

A colon inside the braces introduces a format specifier. :.2f means "fixed-point, 2 digits after the decimal" — the single most useful one for money and measurements.

ready ✓

Teaching tip

Run "Format specifiers" and let the class see the raw floating-point mess in the first line — 21.589199999999998 is ordinary binary floating-point imprecision, the same thing that happens in C++ doubles. The f-string doesn't fix the underlying math; it just controls how the result is displayed.

8.4 · String indexing

Reaching a single character

Square brackets with a position pick out one character. Positive indices count from the left starting at 0; negative indices count from the right starting at −1.

ready ✓

Teaching tip

Try text[12] on a 12-character string and let the class read the real error: IndexError: string index out of range. C++'s std::string::operator[] doesn't bounds-check at all — reading past the end is undefined behaviour, not a clean error. That's a real safety win worth calling out.

8.5 · String slicing

Extracting a substring

Syntax: string_name[start : end : step] — start is where slicing begins (inclusive, default 0), end is where it stops (exclusive, default len(string)), and step is the interval between characters (default 1; negative reverses direction).

ready ✓

Watch this one closely

s[-7:-1] is a common trip-up: with s at 16 characters, -7 lands on index 9 ('S') and -1 lands on index 15 (the final 'e') — but the upper bound is exclusive, so that last 'e' is dropped and the result is 'Scienc', not 'Science'. Run it live and count characters on your fingers with the class; the off-by-one at the end index is the single most common slicing mistake.

Teaching tip

text[::-1] is the idiom every student remembers for reversing a string — no loop, no library call. It's worth deriving live: empty start and end mean "the whole string," and step = -1 means "walk it backward." Compare with C++, where reversing needs std::reverse() or a manual loop over indices.

8.6 · String traversal

Visiting every character, one by one

The process of accessing each character in a string in turn. A for loop over a string does this directly — no index variable required, unlike C++'s typical for(int i=0;i<s.length();i++).

ready ✓

Teaching tip

If a student needs the position as well as the character — say, to print "Index 0: H" — that's exactly what range(len(A)) combined with indexing is for: for i in range(len(A)): print(i, A[i]). Worth contrasting both styles side by side.

Teaching tip

String comparison is case-sensitive and Unicode-based — every uppercase letter sorts before every lowercase letter, since 'A' is code point 65 and 'a' is 97. "Zebra" < "apple" is True, which surprises students who expect dictionary order.

Methods called directly on a string

Beyond operators, strings carry their own methods — called with dot notation, the same syntax as math.sqrt() from Chapter 7, just with a string on the left instead of a module.

Teaching tip

find() and index() do almost the same job, but disagree on failure: find() quietly returns -1, while index() raises a ValueError. Try "apple".find("z") next to "apple".index("z") live — the difference is the whole reason both exist. Also worth flagging: methods return a new string and leave the original untouched, since strings are immutable — "hello".capitalize() doesn't change the literal, it produces one.

Wrap-up

Session summary

Today: what a string is and how it's created, input() and why it always returns a string, f-strings for readable formatting, indexing with positive and negative positions, slicing with start:end:step, traversal with a plain for loop, the three string operators (concatenation, repetition, membership) plus relational comparison, and eight built-in string methods.

Five habits to reinforce with C++ students

  • Strings are immutable — every method that "changes" a string actually returns a brand-new one.
  • input() always returns a string, even for digits — wrap it in int() or float() before doing arithmetic.
  • Slicing's upper bound is exclusive, same off-by-one convention as range() — s[a:b] never includes s[b].
  • Negative indices and negative steps aren't a special case to memorize separately — they're the same indexing rule, just counting from the other end.
  • f-strings replace both +-concatenation and manual str() conversions in one move — and :.2f-style specifiers control display without touching the underlying float.
